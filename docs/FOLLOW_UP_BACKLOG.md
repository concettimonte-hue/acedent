# ACEDENT 후속 작업 목록

이 문서는 대화 전체나 저장소 전체를 매번 다시 분석하지 않고, 보류한 아이디어만 저비용으로 이어서 검토하기 위한 기준 문서입니다.

## 사용 방법

1. 후속 검토를 요청할 때는 `FOLLOW_UP_BACKLOG 기준으로 지금 할 것 1개만 추천해줘`라고 말합니다.
2. AI는 이 문서와 `git status`부터 확인하고, 선택된 항목에 관계된 코드만 읽습니다.
3. 한 번에 한 항목만 진단·구현하며, 사이트 구조 전체 재점검은 명확한 위험이 있을 때만 합니다.
4. 완료·보류·폐기 결정을 이 문서에 짧게 갱신합니다.
5. 보류 항목은 반드시 구현해야 하는 요구사항이 아닙니다. 데이터량과 실제 검색·사용 지표가 조건을 충족할 때만 진행합니다.

상태 표기:

- `운영 중`: 새 기능 없이 운영자가 사례를 등록하며 관리
- `조건부`: 정해진 조건을 충족할 때 다시 검토
- `선택`: 필요성이 생기면 진행
- `완료`: 이미 구현됨
- `하지 않음`: 현재 구조에서는 실익이 낮아 진행하지 않음

## 5. 현재 하지 않는 것

| 항목 | 이유 |
| --- | --- |
| 해시태그 자동 생성 | 일반 웹 검색과 AI 추천에 실익이 낮고 키워드 나열로 보일 수 있습니다. 현재 제목·본문·ALT·내부 링크가 더 중요합니다. |
| `llms.txt` 또는 AI 전용 마크업 | 주요 검색·AI 서비스는 기존 색인 가능 HTML, robots, sitemap과 콘텐츠 품질을 우선합니다. 공식적 실익이 확인되기 전에는 추가하지 않습니다. |
| 기존 사례의 앞·뒤 위치 자동 추론 | `후면`, `측면`, 사진 각도만으로 실제 작업 부위를 단정하면 데이터와 검색 정보가 틀릴 수 있습니다. |
| 사례 수를 늘리기 위한 유사 페이지 복제 | 중복 페이지는 검색 의도를 흐리고 크롤링·색인 효율을 떨어뜨립니다. 실제 작업 1건당 고유 사례 1페이지를 유지합니다. |
| 우클릭·드래그 차단 | 불펌 방지 효과가 낮고 모바일 접근성·사용성을 해칩니다. |
| R2 전체 외부 링크 차단 | 검색 이미지와 SNS 공유 미리보기를 막을 위험이 있어 적용하지 않습니다. |

## 다음 검토 추천 순서

1. 평소에는 사례 등록에 집중합니다.
2. 사례가 10건 더 늘면 `SEARCH-01`을 한 번 확인합니다.
3. 앞·뒤 위치 데이터가 충분해지면 `FILTER-01`의 건수 조건을 확인합니다.
4. AI 또는 검색 유입이 실제로 잡히면 `SEARCH-04`를 검토합니다.
5. 기능 요구가 잠잠한 시기에만 `QUALITY-01`을 별도 작업으로 진행합니다.
